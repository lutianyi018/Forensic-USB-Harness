# Forensic Stick — 便携取证 U 盘改造工程

把 `USB-Harness-with-runtime`（dsh 0.1.5-rc.2 免安装 Web 便携版）改造成便携 AI 取证工作站。
本目录是**改造源**：一套 overlay + 安装/初始化脚本，可重复应用到任意一份 USB-Harness 拷贝，
因此天然支持"制作一次母盘、克隆到新盘"。

## 用法

```powershell
# 1) 安装取证层（默认作用于 ..\USB-Harness-with-runtime）
powershell -ExecutionPolicy Bypass -File .\install.ps1

# 2) 初始化盘上三区并锁定固证区（默认盘根 = 取证包所在目录的上一级）
powershell -ExecutionPolicy Bypass -File .\prepare-stick.ps1 -StickRoot X:\

# 3) 制作方建号（可多次执行；身份证号与密码只存哈希）
powershell -ExecutionPolicy Bypass -File .\New-Operator.ps1 -Name 张三 -Id 110101199001011234 -Password 1234

# 4) 正常启动（launch.bat）——取证核心会凭 forensic-stick.json 自动识别盘根
```

> **复制母盘后启动报错？** 用资源管理器整体拷贝母盘时，`data\dsh\profiles\node_modules\`
> 下的「绝对路径 Junction」会退化成空文件夹，启动报
> `plugin tree failed to load: Cannot find package ...`。新版已可**自动重建**（启动时自愈）；
> 也可手动修复：
>
> ```powershell
> powershell -ExecutionPolicy Bypass -File .\Repair-Stick.ps1 -StickRoot X:\
> ```

向固证区投放证据前临时解锁，投完再锁：

```powershell
powershell -ExecutionPolicy Bypass -File .\prepare-stick.ps1 -StickRoot X:\ -Unlock
# ... 投放证据 ...
powershell -ExecutionPolicy Bypass -File .\prepare-stick.ps1 -StickRoot X:\
```

```

```

## 已实现

### 阶段 A · 集成验证
- 确认基座为 dsh 0.1.5-rc.2 Web 版；取证插件经 bundle + profile 挂载；真实启动无 `ERR_MODULE_NOT_FOUND`。
- 关键约束：插件必须同时存在于 app 的 `node_modules` 与 `data\dsh\profiles\node_modules\@deepseek-ai\`（Junction 目录）。

### 阶段 B · 三区布局与固证区只读
- `ctx.forensic` 解析工作区 / 固证区 / 案件区 / device，并支持取证编号（CASE/EVD/ART/SS/TRES）。
- 单调工具守卫：写类工具参数落在固证区 → 拒绝；shell 命令触及固证区 → 拒绝；读类放行；`device.key`/`.credentials.yaml` 读写一律拒绝。
- NTFS ACL：固证区与 device 对当前账户拒绝**写入 / 删除**（掩码 `WD,AD,WEA,WA,DE,DC`），读 / 列举 / 统计仍允许。
  **不要用通用 `W`**：`W` = `FILE_GENERIC_WRITE` 含 `SYNCHRONIZE`，而 libuv/Node 每次打开文件都要 `SYNCHRONIZE`，会连 `stat`/读取一起拒掉（表现为启动 `mkdir 固证区 EINVAL` 崩溃、AI 也读不了证据）。重复执行 `prepare-stick.ps1` 幂等，可就地修复旧掩码。
- 单测：`tests/policy.test.mjs`（10 项全过）。

### 阶段 C · 操作员登录
- 登录页（内置品牌与轻量动画），凭证为**姓名 + 身份证号 + 密码/PIN**。
- 服务端校验：错误凭据 → 401；正确 → 302/303 种下签名会话 cookie `forensic-op`（HttpOnly）。
- index 门禁：主界面加载前检测会话 cookie，未登录一律重定向到 `/forensic/login`。
- 存储安全：身份证号与密码都只落哈希（PBKDF2-SHA256 + 全局盐），不写明文。
- 建号工具：`New-Operator.ps1` / `tools/operator-cli.mjs`，与登录插件共用同一套算法。
- 单测：`tests/auth.test.mjs`（11 项全过）；HTTP 实测通过。

### 阶段 D · 取证角色、技能与工具总线
关键认知：**Web 档位把 agent 层（persona / fs / skill / plan-mode）移到「agent preset」后面**，host 层这些行被禁用。
因此取证角色与技能做成一个**取证预设**，工具总线做在主机层。

- 取证预设 `data/dsh/.agent-presets/forensic/`：persona 换成取证助手（写死结论分级与固证区只读纪律）；
  只挂载读类工具 + `write`/`edit`（落工作区）+ 技能提供方 + 计划模式；**不含 shell、不含联网检索、不含子代理**。
- 默认预设已指向 `forensic`（`agent-presets` 行的 config 覆盖）。
- 技能：`forensic/skills/**/SKILL.md`（usb-history / registry-analysis / timeline-building 三个示例），
  由预设的 `skill-filesystem` 经 `customSkillDirs` 发现。
- 工具总线 `dsh-forensic-tools`（主机层）：扫描 `forensic/tools/**/manifest.json`，校验后逐个注册为模型工具
  `forensic_<id>`；执行时只用清单声明的参数、可执行文件必须在工具根内（防穿越）、不经 shell、捕获输出并落产物。
- 单测：`tests/tools.test.mjs`（初版 11 项，后随参数形态扩展至 17 项，见阶段 K）；`--dump-config` 确认默认预设与各行生效；启动无警告。

### 阶段 E · 母盘与发放
唯一要紧的规则：**软件复制，身份不复制。**

- `tools/provision.mjs` 提供 `plan`（预演）/ `new-device`（发新盘）/ `device`（补发身份）/ `validate`（校验）。
- 克隆按桶过滤：复制软件；**不复制**身份（`device/**`、`config/forensic-auth.secret`）与每盘数据
  （固证区、案件区、会话/存储/凭据/日志、profile 的 `node_modules`）。
- 新盘发放一枚**全新**设备身份（`FRS-YYYY-NNNNNN`，ID 由母盘台账 `provision/issued.json` 顺序分配），并写入 `device.key`；
  已有身份时拒绝覆盖。
- 首启兜底：取证核心在启动时若发现本盘无身份，会就地生成一枚（`FRS-YYYY-<6位随机>`）。
- 单测：`tests/provision.test.mjs`（初版 28 项，后随分桶断言补充至 30 项，见阶段 I）；对真实盘根 `plan` 显示"身份复制数 0"。

### 阶段 F · 界面换肤、启动动画与侧边栏面板
- **换肤**：覆盖 `dsh-client-ui-brand-official` 的客户端半侧，换成 ForensicDSH 的放大镜+盾牌标识与名称；
  同步写入 `brand-patch/`（供 `launch.bat setup` 重放）与已安装的 `node_modules`。
- **启动动画**：登录插件注册 `/forensic/splash.css` 与 `/forensic/splash.js`，并经 index 注入 `<title>` 与标签；
  splash 在主界面挂载前显示、挂载后淡出（同时承载未登录门禁）。
- **侧边栏入口**：`dsh-client-ui-forensic` 是客户端插件，注册进 `sidebar.panellist` 槽作为导航条目；
  其宿主半侧提供 `/forensic/info`（设备身份 / 三区路径 / 已注册工具 / 技能）。
  （面板形态在**阶段 K**重构为「侧栏入口 + 主画面状态面板」。）
- 实测：`/forensic/info` 返回工具与技能；index 注入生效；组合 bundle 含面板模块与 `sidebar.panellist` 注册。

### 阶段 G · 测试与硬化
- 一键测试：`node tests/run-all.mjs <harnessRoot>` —— policy 10 + auth 11 + tools 11 + preflight 7 + provision 30 = **69 项全过**（当时快照；tools 后扩充至 17，当前完整为 **75 项**，见阶段 K）。
- 端到端冒烟：登录页可用、错误凭据 401、正确凭据发会话 cookie、面板数据接口返回工具与技能、主界面注入标题与 splash。

### 阶段 H · 工具总线加固
- **执行前预检（失败即拒）**：工作区可写探针 + 剩余空间保留额（默认 256 MiB）。U 盘被拔出 / 只读 / 空间不足时，工具**不执行**，返回 `PREFLIGHT_DENIED`，保证产物与审计仍能落盘。
- **可选沙箱围栏**：`forensic-tools` 的 `sandboxMode` 一旦设置（如 `workspace-write`），执行经 `ctx.sandbox.confine` 重新包装 argv；
  不可用时**失败关闭**（`SANDBOX_UNAVAILABLE`），绝不静默放行。默认留空 = 直接运行清单可执行文件（仍不经 shell）。
- 单测：`tests/preflight.test.mjs`（7 项）。

### 阶段 I · 复制可移植性（Junction 失效修复）
- **问题**：`data\dsh\profiles\node_modules` 内是 240+ 个**绝对路径 Junction**，指向 `.cache\app\node_modules`。
  用资源管理器整体拷贝母盘到新盘时，Junction 会退化成「空占位目录」；而 dsh 启动自愈把「已存在的真实目录」
  当作上一轮复制回退的成果而跳过 → 启动报 `plugin tree failed to load: Cannot find package ...`。
- **修复一（自动自愈）**：给 `dsh-app-boot` 的 `ensureSymlink` 打补丁——真实目录**必须含包内容**
  （`package.json` / `index.js`）才算就绪；空占位则删除并按当前盘符重建。任何一次启动都会自动修复被破坏的链接。
- **修复二（显式修复）**：新增 `Repair-Stick.ps1`，把 `app\node_modules` 结构按当前盘符重新镜像进
  `profiles\node_modules`（保留含内容的真实目录、重建空占位 / 错误目标）。
- **接入**：`install.ps1`（第 5/5 步）与 `New-Stick.ps1`（发放后）自动调用修复；`provision.mjs` 把
  `profiles/node_modules` 归为「每盘数据」不再复制。
- 单测：`tests/provision.test.mjs`（30 项，含两条新分桶断言）。

### 阶段 J · 登录门禁修复（HttpOnly 与前端判断）
- **问题**：会话 cookie `forensic-op` 为 `HttpOnly`，而前端门禁 `splash.js` 用 `document.cookie`
  判断「是否已登录」——`HttpOnly` 对 JS **不可见**，于是登录成功后前端仍认为未登录，
  被无限重定向回登录页（表现为「登录成功却一直停在登录界面」）。
- **修复**：登录成功时同时下发两个 cookie——`forensic-op`（`HttpOnly`，真正的会话，服务端校验用）
  与 `forensic-ui=1`（非 `HttpOnly`，仅供前端门禁判断）；登出时两者一并清除；前端门禁改判 `forensic-ui`。
- 说明：前端门禁仍是「体验层」；真正的访问控制由 dsh 自带 browser-trust token 栅栏承担。

### 阶段 K · 界面重构、文档与工具参数扩展
- **侧栏面板重构**：早期把整块信息卡直接塞进 `sidebar.panellist` 的图标位，窄侧栏下显示不全。
  改为「**侧栏导航条目**（`sidebar.panellist`，宽栏=图标+文字、窄栏=纯图标）+ **主画面状态面板**（`main` slot，key=`forensic`）」。
  面板展示：设备身份（设备号 / 发放时间 / 签名密钥）、三区状态（固证区 只读 · 案件区 读写 · 工作区）、
  取证工具（已就绪 / 待投放）、取证技能。
- **主题适配**：面板配色改用宿主主题变量 `--dsw-alias-*`，浅 / 深色自动跟随（不再在 JS 里硬编码颜色）。
- **接口字段归一**：`/forensic/info` 把后端 `snake_case`（`device_id` / `created_at` / `cases`）折叠为
  UI 友好的 `camelCase`（`id` / `issuedAt` / `casework`），并补 `hasKey`（device.key 是否存在）。
- **工具参数形态扩展**：清单 `args` 支持位置参数、带值选项（`--flag value`）、等号选项（`--flag=value`）与布尔开关；
  工具总线单测由 11 项扩充到 **17 项**。
- **文档**：`README.md` 补齐工具定位 / 目录 / 教程 / 工具清单 / 安全模型 / 排错 / 测试 / 许可；
  `docs/使用说明.md` 由 9 节扩到 16 节（新增：内置工具清单、添加工具、添加技能、更新已发盘、安全模型、测试、许可）。
- **实盘验证**：E 盘母盘与 F 盘工作盘均通过「登录 → 侧栏入口 → 面板渲染」检查（深浅色两种主题）。
- 单测：`node tests/run-all.mjs <harnessRoot>` —— policy 10 + auth 11 + tools 17 + preflight 7 + provision 30 = **75 项全过**。

## 安全不变量

| AI 目标 | 结果 | 手段 |
|---|---|---|
| 工作区 / 案件区 | 读 + 写 | 会话 workspace |
| 固证区 | **只读** | 单调守卫（写类拒绝、读放行）+ NTFS `DENY(WD,AD,WEA,WA,DE,DC)`（不用通用 `W`：其含 `SYNCHRONIZE`，会让 Node 连读都失败） |
| 凭据 / 设备密钥 | 拒绝 | 守卫拒绝 `device.key`、`.credentials.yaml` |
| 任意 shell | 拒绝 | 取证预设不含 pwsh / bash |
| 未注册工具 / 任意可执行文件 | 拒绝 | 工具总线只跑清单声明项，且必须落在工具根内 |
| 联网检索工具 | 拒绝 | 取证预设不含 web 工具 |
| 未登录访问界面 | 重定向登录页 | splash.js 门禁 + 服务端凭据校验 |

## 后续可选项

- 登录**强门禁**：目前对 `/` 是前端重定向（凭据在服务端校验）；若要"未登录连 API 都调不动"，需在 `/api` 网关层加会话校验。
- 工具总线的**沙箱围栏默认关闭**（`sandboxMode` 留空）：默认直接运行清单声明的可执行文件（不经 shell，无注入面）；
  需要 syscall 级围栏时在 bundle 里把 `sandboxMode` 设为 `workspace-write`。

## 已知边界与说明

- 登录门禁对 `/` 是**前端重定向**，凭据校验在服务端完成；网络侧的访问控制由 dsh 自带 browser-trust token 栅栏承担，
  因此尚未登录者若持有 token 理论上仍可直接调用 API。**服务端强门禁**（拦 API）留待阶段 G 硬化。
- 盘上三区靠 `forensic-stick.json` 标记识别盘根；`FORENSIC_ROOT` 环境变量可覆盖。
- 名单缺失时登录门禁自动关闭（避免把人锁在外面）；制作方须至少建一个操作员。
- 所有 `.ps1` 以 UTF-8 BOM 保存（Windows PowerShell 解析中文所需）。
- 母盘→新盘的**插件链接**依赖 NTFS 上的 Junction：exFAT/FAT32 无法创建链接，只能退回「目录复制」（占空间、慢）。
  **U 盘请使用 NTFS。**
