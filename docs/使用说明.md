# ForensicDSH 便携取证 U 盘 · 使用说明

> 母盘制作 · 新盘发放 · 日常使用 · 工具扩展
> 面向第一次接触本项目的同事
> 适用产品：ForensicDSH 0.1.0

## 一、这是什么

我们把一套「免安装的便携 AI 取证工作站」装进 U 盘。插入电脑、双击一个批处理文件、用浏览器登录，即可用自然语言指挥 AI 完成取证；原始证据放进「固证区」后只进不改，AI 只能读、不能动。

制作一次**母盘**，就能像刻录一样复制出任意多枚**新盘**——每枚盘都有自己独立的设备编号。

## 二、先认识几个名词

| 名词 | 含义 |
|---|---|
| 盘根 | U 盘的根目录（所有内容的第一层）；本套件以盘根为运行基准 |
| 母盘 | 已装好取证层、并建好操作员名单的那枚 U 盘，用来复制新盘 |
| 新盘 | 从母盘复制出来、拥有独立设备编号的 U 盘 |
| 工作区（程序目录） | 盘根下的 `USB-Harness-with-runtime` 文件夹：AI 框架、运行时、取证工具与脚本（可读写） |
| 固证区 | 存放原始证据；只进不改，AI 只读 |
| 案件区 | 保存案件记录与工作副本（可写） |
| device | 本盘身份（设备编号 device.json 与密钥） |
| config | 操作员名单 operators.json 与登录会话密钥 |
| forensic-stick.json | 盘标记；程序据此识别盘根 |

> **别把两个「工作区」搞混**：上表的「工作区」指**程序目录**（装框架与工具的地方）；
> 而登录后界面让你「选择工作区」，选的是**你办案用的目录**——建议选 `案件区`，详见第六节。

## 三、你会用到的东西

- 一台 Windows 10/11 电脑（64 位）
- U 盘（建议 NTFS 格式，原因见第十三节）
- 基座文件夹 `USB-Harness-with-runtime`（免安装，随本套件提供）
- 取证包文件夹 `forensic-stick`（含全部脚本，随本套件提供）

## 四、制作母盘（只需做一次）

1. **放入基座**：把整个 `USB-Harness-with-runtime` 文件夹拷到 U 盘根目录，使其成为「盘根\USB-Harness-with-runtime」。
2. **安装取证层**：打开取证包 `forensic-stick` 目录，右键「在终端中打开」，执行：
   ```powershell
   powershell -ExecutionPolicy Bypass -File .\install.ps1 -Target <盘根>\USB-Harness-with-runtime
   ```
   （若取证包与 `USB-Harness-with-runtime` 是同级目录，可省略 `-Target`。）
3. **初始化并上锁**：
   ```powershell
   powershell -ExecutionPolicy Bypass -File .\prepare-stick.ps1 -StickRoot <盘根>
   ```
   这会在盘根建立 `固证区 / 案件区 / device`，写入盘标记，并给固证区与 device 加上「拒绝写入」权限。
4. **建操作员**（可重复执行，每人一条）：
   ```powershell
   powershell -ExecutionPolicy Bypass -File .\New-Operator.ps1 -Name 张三 -Id 110101199001011234 -Password 1234
   ```
5. **验证**：双击「盘根\USB-Harness-with-runtime\launch.bat」，浏览器会自动打开；出现登录界面即成功。

## 五、制作新盘（每枚新 U 盘做一次）

前提：母盘已按第四节点亮。把新 U 盘插上、格式化好（建议 NTFS），记住它的盘符（下称 `<新盘盘根>`）。

1. **发放**：
   ```powershell
   powershell -ExecutionPolicy Bypass -File .\New-Stick.ps1 -Source <母盘盘根> -Target <新盘盘根>
   ```
   程序把「软件」复制到新盘，并给新盘发放一枚**全新**设备编号（形如 `FRS-2026-000001`）；母盘的设备身份、会话密钥与固证区内容**不会**被复制。
2. **上锁固证区**：
   ```powershell
   powershell -ExecutionPolicy Bypass -File .\prepare-stick.ps1 -StickRoot <新盘盘根>
   ```
   （文件权限不会被「复制」，所以新盘需要再上锁一次。）
3. **校验**：`New-Stick.ps1` 发放后会自动校验；如需单独校验，用便携 node 运行：
   ```powershell
   <盘根>\USB-Harness-with-runtime\.cache\runtimes\windows-x64\node\node.exe tools\provision.mjs validate --target <新盘盘根> --expect-identity
   ```
   看到「校验通过」即可。

> **手动复制的补救**：如果你不是用 `New-Stick.ps1`，而是直接用资源管理器把母盘整个文件夹拷到新盘，
> 插件链接可能会失效（表现见第十三节）。在新盘上跑一次修复脚本即可：
> ```powershell
> powershell -ExecutionPolicy Bypass -File .\Repair-Stick.ps1 -StickRoot <新盘盘根>
> ```
> 说明：`New-Stick.ps1` 与 `install.ps1` 现在都会**自动**执行这一步（New-Stick 发放、install 安装取证层之后）。

## 六、日常使用

1. 插入 U 盘，双击「盘根\USB-Harness-with-runtime\launch.bat」，浏览器自动打开。
2. 在登录界面输入 **姓名 + 身份证号 + 密码**，登录。
3. **首次启动会让你「选择工作区」，请选 `案件区`**（例如 `X:\案件区`）。
   - 你选的这个「工作区」就是 AI 的**可写边界**：AI 只能往它里面**写**文件；**读**不受限，固证区照样读得到。
   - **别选固证区**：AI 写不进去，任务会一直报沙箱拒绝，没有意义。
   - **别选盘根 `X:\`**：那会让 AI 对整个盘可写（包含程序目录），误改工具与框架的风险大。
   - 取证工具的产物固定落在 `USB-Harness-with-runtime\forensic-out\`，**与所选工作区无关**；需要归档时手动拷进案件区。
   - 想更干净：可在案件区下建一个子目录（如 `案件区\AI工作区`）再选它，把「AI 自产文件」与正式案件记录分开。
4. 左侧侧栏的「**取证工作区**」条目可查看：本盘设备编号、固证区 / 案件区状态与路径、已装取证工具与技能。
5. 用自然语言下达取证任务（例如「分析这台电脑的 USB 使用记录并生成时间线」），AI 会按流程执行。
6. 往固证区投放原始证据前需临时解锁，投完立即上锁：
   ```powershell
   # 解锁
   powershell -ExecutionPolicy Bypass -File .\prepare-stick.ps1 -StickRoot <盘根> -Unlock
   # …… 把证据放进 固证区\ ……
   # 上锁
   powershell -ExecutionPolicy Bypass -File .\prepare-stick.ps1 -StickRoot <盘根>
   ```

## 七、内置与可扩展的工具

本工程把取证工具以「**清单（manifest.json）+ 可执行文件**」的形式放进 `forensic\tools\`，启动时自动发现，
注册成模型可见的工具 `forensic_<id>`。

**① 随盘内置（可直接调用，均为可再分发许可）**

| 工具 | 用途 | 形态 / 许可 |
|---|---|---|
| osquery | 本机实时状态 SQL 查询（进程 / 服务 / 网络 / 用户 / 开机自启 / 计划任务 / 已装软件），JSON 输出 | 单 exe，Apache-2.0 |
| Sleuth Kit CLI（`fls` / `mmls` / `fsstat` / `icat`） | 磁盘、文件系统与镜像检视 | exe + DLL（共享 `bin/`），CPL / IPL |
| WinPmem | 物理内存采集（需管理员） | 单 exe，Apache-2.0 |

对应的模型可见工具名：`forensic_osquery`、`forensic_tsk_fls`、`forensic_tsk_mmls`、`forensic_tsk_fsstat`、`forensic_tsk_icat`、`forensic_winpmem`。

**② 已备清单、需自行投放二进制**

| 工具 | 用途 | 许可 / 说明 |
|---|---|---|
| EZ Tools（`MFTECmd` / `EvtxECmd` / `PECmd` / `JLECmd`） | NTFS $MFT / 事件日志 / Prefetch / JumpList 解析 | MIT；需 .NET，见 `forensic\tools\external\ez-tools\README.md` |

**③ 仅给链接（许可不允许随本套件再分发）**

| 类别 | 推荐 | 链接 |
|---|---|---|
| 内存获取 | Magnet DumpIt / RAM Capture | 官方页面（专有免费） |
| 内存分析 | Volatility 3 | github.com/volatilityfoundation/volatility3 |
| 浏览器痕迹 | Hindsight / BrowsingHistoryView | github.com/RyanDFIR/hindsight（Apache-2.0）；nirsoft.net |
| 即时通讯 | TGArtifacts / telegram-desktop-decrypt | github.com/Dmeetrogon/TGArtifacts；github.com/atilaromero/telegram-desktop-decrypt（MIT） |

**怎么区分「已装好」和「待投放」**：侧栏「取证工作区」面板会把两者分开列——
「已就绪（二进制已安装）」= 可调用；「待投放（仅有清单，缺二进制）」= 还差可执行文件。

## 八、添加取证工具（重点）

工具总线在启动时递归扫描 `forensic\tools\**\manifest.json`，把每个工具注册为 `forensic_<id>`；
**参数按清单声明顺序拼成命令行、不经 shell**（因此没有命令注入面）。

**放哪里**

- **开发 / 源**：`forensic-stick\overlay\harness\forensic\tools\external\<工具>\`（`install.ps1` 会拷到盘上）；
- **盘上**：`<盘根>\USB-Harness-with-runtime\forensic\tools\external\<工具>\`（直接生效）。
- 该目录在 runtime 内，属于「软件」，**母盘放一次，之后复制的新盘都会带上**，无需每盘再放。

**清单最小形态**

```json
{
  "id": "usb-history",
  "name": "USB History Extractor",
  "version": "1.0.0",
  "description": "从 SYSTEM hive 提取 USB 连接历史。",
  "executable": { "windows": "usb-history.exe" },
  "args": [
    { "name": "evidence_path", "type": "string", "required": true, "description": "SYSTEM hive 路径" }
  ],
  "timeout_ms": 300000
}
```

**字段说明**

| 字段 | 必需 | 说明 |
|---|---|---|
| `id` | 是 | 工具标识；模型可见工具名由它派生为 `forensic_<id>` |
| `name` | 是 | 显示名 |
| `executable.windows` | 是 | 可执行文件路径，**相对本工具目录**，且必须落在 `forensic\tools` 之内（防目录穿越） |
| `args[]` | 否 | 参数声明，决定模型可见的参数 schema 与 argv 组装顺序 |
| `timeout_ms` | 否 | 执行超时（毫秒），默认 300000 |
| `requires_admin` | 否 | 是否需管理员（当前仅记录，不自动提权） |
| `network.allowed` | 否 | 是否允许联网（当前仅记录） |

**参数三种写法**（`args` 里每一项）

| 写法 | 效果 | 例 |
|---|---|---|
| 位置参数（默认，不带 `flag`） | `<值>` | `fls image.dd` |
| 带值选项 `"flag": "--csv"` | `--csv <值>` | `MFTECmd -f a.bin --csv out` |
| 等号选项 `"flag": "--json", "style": "equals"` | `--json=<值>` | `tool --json=x` |
| 开关 `"type": "boolean"` | 为 `true` 时输出该名（或 `flag` 指定的名） | `-accepteula`、`-r` |

> 参数按 `args` 声明顺序输出；**未声明的输入一律丢弃**。

**多个工具共用一套二进制（省空间）**：可执行路径是「相对本工具目录」的，所以可把公共二进制放一个 `bin/`，
各清单用 `..` 指过去：

```
forensic\tools\external\sleuthkit\
├── bin\                 # fls.exe / icat.exe / ... 及依赖 DLL（无 manifest，不注册）
├── fls\manifest.json    # { "executable": { "windows": "../bin/fls.exe" } }
└── mmls\manifest.json   # { "executable": { "windows": "../bin/mmls.exe" } }
```

**加完后**：重启 `launch.bat` 即可，工具会出现在侧栏「取证工作区」面板，模型可直接调用 `forensic_<id>`。
**只放清单、缺二进制**时，只会显示在「待投放」里，不会被注册。

## 九、添加取证技能

技能是给 AI 的**方法论提示**（怎么按取证流程做事），放在：

```
forensic\skills\<域>\<名字>\SKILL.md
```

随 runtime 一起复制到新盘。内置三个示例：

| 技能 | 域 | 用途 |
|---|---|---|
| `usb-history` | acquisition | USB 连接历史提取与解读 |
| `timeline-building` | timeline | 多源时间线构建与呈现 |
| `registry-analysis` | windows | 注册表痕迹分析 |

## 十、更新已发出的盘

工具 / 插件有更新时，有两种做法：

1. **并入母盘后重新复制**（推荐，一次到位）：更新母盘 → 用 `New-Stick.ps1` 重发新盘。
2. **只更新单枚盘**：
   ```powershell
   powershell -ExecutionPolicy Bypass -File .\install.ps1 -Target <盘根>\USB-Harness-with-runtime
   powershell -ExecutionPolicy Bypass -File .\Repair-Stick.ps1 -StickRoot <盘根>
   ```
   （`install.ps1` 覆盖插件层；`Repair-Stick.ps1` 重建插件链接。）

> **界面（客户端）改动后**：浏览器可能仍缓存旧的界面代码，首次访问请按 **`Ctrl + F5`** 强制刷新。

## 十一、脚本一览

| 脚本 | 作用 |
|---|---|
| `install.ps1` | 把取证层安装进某个基座拷贝（`-Target` 指定基座目录；安装后自动重建插件链接） |
| `prepare-stick.ps1` | 建立三区、写盘标记、给固证区 / device 上锁；`-Unlock` 临时解锁 |
| `New-Operator.ps1` | 新增操作员（姓名 + 身份证号 + 密码/PIN），可多次 |
| `New-Stick.ps1` | 从母盘复制出一枚新盘并发放独立设备身份（发放后自动重建插件链接） |
| `Repair-Stick.ps1` | 重建插件链接（`profiles\node_modules`）；复制母盘后若启动报模块缺失，跑它即可 |
| `tools\provision.mjs` | 发放底层命令：`plan` / `new-device` / `device` / `validate` |
| `tests\run-all.mjs` | 一键自检（可选，见第十四节） |

## 十二、安全模型

| 目标 | 结果 | 手段 |
|---|---|---|
| 读取（含固证区） | **允许** | 沙箱只拦「写」，不拦「读」 |
| 写入选定的工作区 | **允许** | 选工作区 = 划定可写边界 |
| **写入 / 删除固证区** | **拒绝** | 单调策略守卫（写类操作直接拒）+ NTFS 拒绝写入权限 |
| 读取或写出 `device.key`、`.credentials.yaml` | **拒绝** | 策略守卫按文件名拦截 |
| 任意 shell（pwsh / bash） | **拒绝** | 取证预设不含 shell 工具 |
| 联网检索 | **拒绝** | 取证预设不含 web 工具 |
| 未注册的可执行文件 | **拒绝** | 工具总线只跑清单声明、且落在工具根内的文件 |

> 三点补充：
> 1. **固证区有两层保护**：软件守卫（始终生效）+ Windows 文件权限（仅 NTFS 有效）。
> 2. **前端登录门禁是体验层**；网络侧的访问控制由基座自带的 browser-trust token 栅栏承担。
> 3. 固证区权限**不用通用 `W`**（它含 `SYNCHRONIZE`，会让程序连读都失败），只拒绝「写入 / 删除」的具体权限位。

## 十三、注意事项

- **固证区只读有两层保护**：软件守卫（始终生效）+ Windows 文件权限（仅 NTFS 有效）。若 U 盘为 exFAT/FAT32，权限层不会生效，建议格式化为 NTFS。
  - 权限层只拒绝「写入 / 删除」这几个权限位，**读、列举、统计照常允许**（这样 AI 能读证据、程序能正常启动）。切勿改回通用 `W`（它含 SYNCHRONIZE，会让程序连读都失败）。
  - 若曾用**旧版本**锁过固证区，请重新执行一次 `prepare-stick.ps1`（脚本会先清掉旧拒绝项再写新掩码，幂等且可就地修复）。
- **操作员名单缺失时登录门禁会自动关闭**（防止把人锁死），制作方务必至少建一名操作员。
- **中文参数请通过 `New-Operator.ps1` 传入**（脚本已处理编码），不要直接在命令行里拼中文。
- 启动若报 `ERR_MODULE_NOT_FOUND`，说明取证层没装全，重跑第四节第 2 步。
- 启动若报 `dsh: plugin tree failed to load` / `Cannot find package '...\profiles\node_modules\...'`：这是「母盘被整体复制后，插件链接退化成空文件夹」导致的（Junction 是绝对路径，普通复制会破坏它）。两种解法：① 直接双击 `launch.bat` 启动，新版会**自动重建**这些链接（无需人工干预）；② 若仍失败，手动跑 `Repair-Stick.ps1 -StickRoot <盘根>` 修复后重试。**注意：U 盘必须是 NTFS**（重建链接依赖 NTFS；exFAT/FAT32 无法创建链接）。
- 启动若报 `EINVAL: invalid argument, mkdir '...\固证区'`（同样表现为 `plugin tree failed to load`）：这是**固证区的文件权限用了旧版通用 `W` 掩码**，导致程序连该目录都读不了。重新执行一次 `prepare-stick.ps1 -StickRoot <盘根>` 即可就地修复（新版已改为只拒绝写入/删除的具体权限位）。
- 登录成功却一直停在登录页（来回跳转）：说明该盘用的是旧版登录插件。重跑一次 `install.ps1 -Target <盘根>\USB-Harness-with-runtime`（更新取证插件包）后重试即可（新版登录成功会同时下发一个前端可见的标记 cookie）。
- 侧栏看不到「取证工作区」条目：先按 `Ctrl + F5` 强刷；仍无则重跑 `install.ps1` 更新插件包。
- 工具不出现：确认 exe 与 `manifest.json` 在同一工具目录、且 exe 落在 `forensic\tools` 之内；重启工作站。
- 工具报 `PREFLIGHT_DENIED`：工作区不可写，或剩余空间不足 256 MiB。
- 母盘与新盘建议各留备份；新盘设备身份唯一，丢失后可用 `provision.mjs` 的 `device` 命令补发。

## 十四、测试

在取证包目录下，用便携 node 一键跑全部单元测试：

```powershell
cd <取证包>\forensic-stick
<盘根>\USB-Harness-with-runtime\.cache\runtimes\windows-x64\node\node.exe tests\run-all.mjs <盘根>\USB-Harness-with-runtime
```

覆盖策略守卫、登录鉴权、工具发现/校验/组装、执行前预检、发放分桶等，全部通过会输出「全部通过」。
